# PR description

1. Read PR metadata, changed files, commits, and only enough diff to understand behavior.
2. Preserve the existing PR template/structure.
3. State only claims supported by the current diff and actual validation.
4. Include what/why, relevant backend/performance implications, and validation.
5. Do not modify code. Keep concise. Stop.
